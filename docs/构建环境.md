Wrapper 使用 Gradle 官方分发地址，校验值已写入 `gradle/wrapper/gradle-wrapper.properties`：

```text
d725d707bfabd4dfdc958c624003b3c80accc03f7037b5122c4b1d0ef15cecab
```

标准 Maven Central、Google Maven 和 Gradle Plugin Portal 均保留；Android 坐标先使用阿里云 Google Maven 镜像，减少本机访问 Google Maven 的超时。Google 仓库限制为 Android 相关组，Kotlin 等普通依赖直接走 Maven Central。

## 本机已验证的入口

首选从 Ubuntu / WSL2 进入项目：

```bash
cd /mnt/e/机器学习实验作业
bash scripts/build.sh
```

无参数会运行 `assembleDebug`、`testDebugUnitTest`、`lintDebug`。也可以指定任务：

```bash
bash scripts/build.sh :app:compileDebugKotlin
bash scripts/build.sh :app:testDebugUnitTest
bash scripts/build.sh :app:assembleRelease
```

脚本会优先使用完整 Linux JDK / SDK；WSL 缺少 Linux Java 或 Linux Build Tools 时，自动调用现有 Windows PowerShell、Windows JDK 与 SDK，并在终端明确显示执行环境。本次使用这条回退路径，理由是 Ubuntu 起初无 Java、无 Linux Android SDK，官方工具下载缓慢，而 Windows 已有完整 SDK。初次准备曾下载 Linux JDK 和命令行工具，随后取消尚未完成的下载；这些下载不构成 Linux 工具链安装成功的证据。

当前 Windows 路径：

```text
JAVA_HOME=C:\Program Files\Java\jdk-21.0.10
ANDROID_HOME=E:\Android\Sdk
GRADLE_USER_HOME=E:\Android\Gradle
```

Gradle 分发已通过上述 SHA-256 核验。`bash scripts/build.sh --version` 已实际返回 Gradle 8.9 / Oracle JDK 21.0.10 / Windows 11；这仅证明入口与工具可运行，应用的编译、测试及 lint 结果见 `验证记录.md`。

直接在 PowerShell 构建，使用已处理中文路径兼容性的入口：

```powershell
Set-Location -LiteralPath 'E:\机器学习实验作业'
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21.0.10'
$env:ANDROID_HOME = 'E:\Android\Sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:GRADLE_USER_HOME = 'E:\Android\Gradle'
.\scripts\build-windows.ps1
# 指定任务：
.\scripts\build-windows.ps1 -Tasks @(':app:assembleDebug', ':app:testDebugUnitTest', ':app:lintDebug', ':app:assembleDebugAndroidTest')
```

换一台机器可设置 `JAVA_HOME`、`ANDROID_HOME` 并使用 wrapper；首次构建需联网下载依赖。若通过 WSL 调用另一套 Windows 工具，可设置 `TRAVEL_WINDOWS_JAVA_HOME`、`TRAVEL_WINDOWS_ANDROID_HOME`；显式选择回退模式可设置 `TRAVEL_BUILD_PLATFORM=windows`。

源码目录含中文，项目设置了 Android Gradle Plugin 的 `android.overridePathCheck=true`。本机直接运行 Gradle 可以打包，但 Windows Java 读取 Gradle 测试参数文件后将中文类路径读错，四个测试类均报 ClassNotFoundException；诊断程序复现了参数文件中的项目名丢失。

`scripts/build-windows.ps1` 检测到非 ASCII 路径时，会在系统临时目录新建独立英文目录，仅复制应用源码和构建文件，逐文件核对 SHA-256 后执行相同 Gradle 任务。原项目保留，构建输出和报告复制回原项目 `app/build/`。临时源码清单和目录记录位于 `.tools/android-checks/`；可用 `-BuildRoot 'D:\TravelBuilds'` 指定其他英文临时根目录。脚本不复制手账备份、API 设置、Git 或下载缓存，也不自动删除旧副本。

WSL 回退 Windows 时同样走这个入口。完整 Linux 工具链可直接使用 Linux wrapper；英文 Windows 源码目录也可直接运行 Gradle。

## 使用完整 Linux 工具链

安装 JDK 17，以及官方 Linux Android Command-line Tools。通过 `sdkmanager` 安装 `platforms;android-35`、`build-tools;35.0.0`、`platform-tools` 并接受适用许可。将 `ANDROID_HOME` 指向该 Linux SDK 后，脚本直接执行 Linux wrapper。可以使用项目下已被 Git 忽略的 `.tools/android-sdk`，也可以使用其他 Linux 目录。

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
bash scripts/build.sh
```

Windows SDK 的 `.exe` 不能作为 Linux 本机 Build Tools 使用。两个系统的 SDK 和 Gradle 用户缓存应分别设置，避免交替写入同一组本机缓存。

## APK 与签名

Debug 输出：`app/build/outputs/apk/debug/app-debug.apk`，由本机 Android debug key 签名，可安装用于测试。

Release 输出：`app/build/outputs/apk/release/app-release-unsigned.apk`。项目不在源码内保存签名私钥或密码。发布时使用独立私钥、`zipalign` 和 `apksigner` 生成最终 APK，并保存签名验证结果，最终交付文件以 `release/` 目录和 `验证记录.md` 为准。
