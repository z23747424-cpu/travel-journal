# 核心独立检查

该检查用于在 Android Gradle 插件仍下载时，独立编译核心源文件并运行正式 JVM 行为测试。它使用 Android SDK 35 的类型定义，不构建 APK，也不启动 Android。

在项目根目录运行 PowerShell：

```powershell
.\scripts\check-core.ps1
```

脚本检测 Android Studio 中的 Kotlin 编译器、JDK、Android SDK 35，以及 Gradle 缓存或项目 `.tools/core-check/libs` 中的依赖。新机器缺少 JUnit、Hamcrest 或 org.json 时，可明确允许下载固定版本：

```powershell
.\scripts\check-core.ps1 -DownloadMissing
```

JUnit 4.13.2、Hamcrest Core 1.3、org.json 20240303 下载源为 Maven Central；AndroidX ExifInterface 1.3.7 优先使用 Gradle 缓存中的 AAR 并提取 classes.jar，缺失且明确指定下载时使用 Google Maven。协程优先使用缓存中的 1.9.0；否则使用 Android Studio Kotlin 编译器附带的协程 JAR，实际路径记录在日志中。脚本不读取 AI 设置，不需要或写入 API 密钥。

无法自动定位时可指定路径，本机示例为：

```powershell
.\scripts\check-core.ps1 `
  -KotlinHome 'E:\Android\Android Studio\plugins\Kotlin\kotlinc' `
  -AndroidSdk 'E:\Android\Sdk' `
  -JavaHome 'C:\Program Files\Java\jdk-21.0.10' `
  -GradleCache 'E:\Android\Gradle' `
  -DownloadMissing
```

脚本直接启动 `org.jetbrains.kotlin.cli.jvm.K2JVMCompiler`，避免本机 `kotlinc.bat` 解析含空格安装路径失败。真正的 org.json 必须先于 `android.jar` 出现在运行类路径中，否则 Android SDK 的占位实现会抛出 `Stub!`。
