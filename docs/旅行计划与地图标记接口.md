# 旅行计划与自定义省份标记

此次完成的是 `desktop-preview/scrapbook` 电脑交互原型。现有 Android / 同学 AI 模块没有被覆盖，以下模型可作为之后迁移到 Room / Compose 的约定。

## 数据

IndexedDB `lvye-province-scrapbook` 升级 v2，新添 `plans` store。v1 stores 原样保留；升级只创建缺少的 store。计划独立于记录和省份设计，删除计划不删除手账。计划草稿放在 `settings` 的 `plan-draft`，与手账的 `draft` 分开。

```js
{
  id, title, destination, origin, startDate, budget, summary, notes,
  provinceCode: null, // 六位省级代码，由用户选择；海外可为空
  status: 'planned', // planned 关联省份后插旗；draft 仅收藏
  days: [{id, title, activities: [{id, time, place, description, transport, sourceIds: []}]}],
  sources: [{id, title, url}],
  aiGenerated: false, createdAt, updatedAt
}
```

目的地必填；日期选填；1–30 天，每天最多 20 项。没有市级地图标注。保存计划不设置记录 visited。地图存在想去手账或 planned 计划时显示该省标记；已去与想去可以同时存在。

`designs` 的省份独立设计增添可选字段：

```js
marker: {kind: 'flag', color: '#AC7850', size: 24, image: 'data:image/png;base64,...'}
// kind: flag | pin | star | heart | image; size: 16–40 px
```

内置形状颜色可改；图片模式保留原图（含 alpha），不对上传图片染色。标记设置不改变去过状态。JSON v2 包含 plans 和 designs.marker；v1 文件仍可导入，重复 ID 询问是否采用文件版本。导入首先完整验证，失败不写入。AI 凭据和未保存草稿不在导出文件内。

## 浏览器本地桥接

`POST /api/travel`，Content-Type application/json，Origin 必须匹配 `http://127.0.0.1:8778`（端口随服务参数）。没有泛用 URL 代理，不支持重定向或本机/内网 AI 接口。

```js
{
  action: 'recommend', // 或 plan
  needs: '想看海，少走路', origin: '杭州', duration: 3, budget: '每人两千',
  destination: '', // plan 时为所选目的地
  config: {endpoint, model, apiKey, searchKey, consent: true}
}
```

> **已作废（v1.7.0 起）**：下面“先 Tavily 搜索”的说法不再适用，应用不联网搜索；推荐改由 AI 网页版生成，再粘回 JSON。下文关于 plan 结构与客户端补 UUID/省份的约定仍然有效。

先 Tavily 搜索，后调用 Chat Completions。完整 needs 进入模型，来源来自实际检索，不提供内置目的地表。推荐结果：`{destinations:[{name,region,reason,caution,sourceIds}],sources}`。行程结果：`{plan:{title,destination,summary,days:[{title,activities:[{time,place,description,transport,sourceIds}]}]},sources}`；客户端添加 UUID、时间、状态和用户自选省份。

推荐名称必须出现在所引用网页的标题或摘要，引用 ID 必须存在。行程的天数必须匹配，每项地点安排至少引用一个已检索来源。这是来源一致性检查，不是事实核验。服务失败返回 `{error:'可读信息'}`，不会发送伪造结果。UI 可以停止等待，迟到响应不覆盖当前页面；上游调用不保证撤销。

配置仅当前浏览器标签页 sessionStorage，不落服务端、不写备份或日志。服务端不记录请求正文及上游异常正文。Android 可复用现有密钥管理与联网实现，不建议在 Android WebView 内嵌本地 Python 桥接。

## 验证边界

`scripts/test-travel-plans.cjs` 使用隔离浏览器与明确注入的 AI HTTP 响应检查交互，`scripts/test-travel-ai.py` 用注入 transport 检查真实桥接代码，无真实服务密钥。既有记录/地图与边界交互脚本也通过。本轮不声称真实 AI 推理或 Android 真机验证完成。
