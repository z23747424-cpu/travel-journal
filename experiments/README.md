# 课程实验：旅行手账检索与有限目的地推荐

本目录是可复算的教学实验材料，使用 Python 标准库，无额外 Python 包依赖。全部 36 篇手账均为明确虚构的示例，没有用户原始照片、个人记录或实际行程证据。

标注是开发助手根据文字关系预先起草的教学手工样例，尚未经独立人工复核，不是真实用户研究、众包标注或双人一致性评审。相关集合仅适用于本数据版本，未列入的地点不代表在现实中绝不适合。开始计算基线前已固定数据与 SHA-256；不得为提高某种方法的命中率而改答案。若独立复核发现标注错误，保留 v1 和已有报告，另建 v2，并公开更正理由。

## 文件与任务

| 文件 | 内容 |
| --- | --- |
| `journals.json` | 36 篇虚构示例手账的纯文本元数据，`example:true`，`photos:[]` |
| `retrieval_queries.json` | 36 查询：30 条有相关记录、6 条无匹配；含关键词、同义、模糊组合和排除条件 |
| `recommendation_cases.json` | 20 需求：18 条有主题适合候选、2 条资料库外；含排除目的地、地区与标签以及资料不足情形 |
| `dataset_manifest.json` | 首次基线运行前保存的输入 SHA-256，包含应用实际目的地库 |
| `evaluate.py` | 数据校验、确定性基线与度量计算 |
| `run_model.py` | 可选：使用用户自己的 HTTPS Chat Completions 服务执行真实模型测量，或只导出不含答案的输入 |
| `baseline_results.json` | 实际基线逐条结果、耗时、错误、指标与数据哈希；`model:null` |
| `基线实测.md` | 已完成基线的可读汇报，模型明确待测 |
| `check_materials.py` | 冻结数据、实际基线可复算性、指标算例、模型ID与输入隔离检查 |

目的地事实读取 `../app/src/main/assets/destinations.json`，具体来源与边界见 `../docs/目的地资料来源.md`。实验手账中的虚构体验不能反过来作为目的地事实来源。


## 两种方法共享什么

手账基线与模型读取同一份 `journal_fields()` 输出：ID、标题、地点、日期、标签、照片描述、最多 800 字正文。当前样例均小于限长。所有标签与照片描述都是示例作者写出的已确认文本，未让模型获得真实图片或额外标签。标题限 300 字，地点限 300 字，标签最多 30 个且每个限 60 字，描述限 1000 字。字段外的标注、`relevantIds`、说明与示例标志均不进入模型请求。

手账关键词基线复刻当前应用 `Search.kt` 在本数据上的行为：

1. NFKC 规范化、小写；连续中文拆为相邻二字片段，英文/数字作为词；去重。
2. 每个命中片段在标题加 5、地点加 4、标签加 4、正文/描述/日期合并字段加 1；完整查询短语命中额外加 8。
3. 得分大于零才返回；按分数降序、日期降序、ID升序。没有停用词、同义词扩展或训练步骤。
4. 本样例仅有 BMP 常用汉字；Python 的字符范围按这些输入复刻，未声称完整覆盖 Kotlin IsHan 的全部 Unicode 扩展区。

推荐标签基线在同一目的地库上，以 `preferredTags` 交集数排序（并列按ID），返回最多 3 项。地区、排除地区、排除标签和已否决ID执行已知筛选。人工结构化条件同时提供给基线与模型，因此本推荐对照衡量排序与资料使用，不衡量自然语言条件抽取准确率。预算和交通没有进入已知约束字段；r18 只标海边灵感，500元与周末两天的可行性始终待核对。

可查看两种方法共用、不含答案的输入：

```bash
python3 experiments/run_model.py --prepare-only /tmp/travel-journal-shared-inputs.json
```

该命令不调用 API。正式模型检索每批 20 条，覆盖全部 36 篇；合并批次候选后再请求最终 Top-3。若某次调用失败，整条查询记失败并返回空，不用关键词结果冒充模型结果。推荐一次读取 30 条资料和同一结构条件。这是独立 Python 推理实验，未等同于 Android UI、网络栈、识图或完整 App 端到端测试。

## 用户配置后执行真实模型

服务须支持标准 HTTPS Chat Completions。接口基础地址或完整 `chat/completions` 地址均可；不会向跨域重定向继续发送密钥。服务返回严格 JSON，错误格式、未知/重复ID和超限条目记为失败，不自动修出一个看起来正确的结果。

在 Ubuntu 终端中填入自己的服务和模型；密钥通过隐藏输入提供，不写入源码或报告：

```bash
export API_BASE_URL='https://你的服务域名/v1'
export MODEL_NAME='你的多模态或文本模型名'
read -rsp 'API Key: ' API_KEY
export API_KEY
python3 experiments/run_model.py --output experiments/model_results_run1.json
unset API_KEY
python3 experiments/evaluate.py --model-results experiments/model_results_run1.json --output experiments/comparison_run1.json
```

一次完整执行包含 36 条检索、20 条推荐；检索每条2个批次，必要时增加一次合并调用，最多共128次请求。用户自己的服务可能计费。只发送本目录的虚构文本和公开目的地资料，不发送手机相册或整本个人手账。不配置环境变量时脚本退出并说明“模型待测”，不会生成伪造的模型测量。结果文件已存在时要求选新文件名，保留原始证据。

模型结果每条保存ID、理由、待核对条件、调用总耗时及错误。失败也进入固定总分母；不进行静默重试或只挑成功样例。数据哈希不一致、缺少查询、未知ID或重复结果会使评估拒绝继续。HTTP错误只记状态码，不把错误响应正文或密钥写入报告。

## 指标定义与解释复核

- Hit@K：在30条有相关记录的查询中，前K个结果至少命中一个预标注相关ID的比例。无匹配查询另计误报。
- 无匹配误报率：6条相关ID为空的查询中，返回任何结果的条数/6。
- 推荐 Top-3 命中率：18条有候选需求中，前3至少含一个标注适合地点的比例。
- 推荐固定3槽精度：每条前3中标注适合的数量/3，再在18条上平均。返回不足3项的空槽计0，避免只返回1项就被当作完整Top-3精度。
- 返回项目适合度：所有正例需求的前3中适合数量/实际返回数量，作为单独补充。
- 已知条件违反率：返回项目中违反已有地区、排除地区、排除标签或已否决ID的项目数/实际返回项目数。未知票价交通不进入此指标。
- 失败率：该任务失败条数/总条数；时延包含失败请求。基线本机计算耗时与网络调用总耗时应分别呈现。
- 解释有据程度：模型每个item的 `explanationSupported` 默认为 `null`。独立评阅者逐条查看资料原文与条件，确认整段理由无额外无来源断言后标 `true`，否则标 `false`，重新评估得到“已评阅条目”的比例。不得把模型自己说“有据”当作人工验证。基线只列匹配标签，其支持度由程序规则可检查，报告明确区分。
- 推理输出的未知ID作为响应失败计数；对已知ID的硬条件违反使用原始预测ID统计，不通过评估后置过滤将违反隐藏。

记录模型名称、执行时间、数据版本和实际错误，保留原始结果；人工复核在副本中填写，不覆盖原始输出。课程汇报可先说明已实现预训练模型推理应用与基线实验，待配置真实模型后补齐对照列，不能称为自行训练模型。
